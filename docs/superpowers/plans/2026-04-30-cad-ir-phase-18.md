# CAD IR Phase 18 — STEP imports for external parts

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** Add an optional `stepUrl` field to `ExternalPartRef`. When the codegen emits an assembly script, it can import the STEP file via build123d's `import_step()`. Closes the gap between "I declare an external part exists" and "I can compile a real assembly with it."

**Builds on:** Phase 17 tip. Worktree at `~/fabware-cad-ir-phase-18/` on branch `feat/cad-ir-phase-18`.

---

## Tasks

### Task 1: Extend ExternalPartRef with stepUrl

`convex/cad/ir/types.ts`:

```ts
export interface ExternalPartRef {
  id: PartId;
  kind: "external";
  vendor: string;
  partNumber: string;
  description?: string;
  origin?: { x: ParamRef; y: ParamRef; z: ParamRef };
  rotation?: { rx: ParamRef; ry: ParamRef; rz: ParamRef };
  boundingBox?: { width: ParamRef; height: ParamRef; depth: ParamRef };
  /** Optional STEP file URL (https://...) — codegen will emit import_step(...). */
  stepUrl?: string;
}
```

Zod (`schema.ts`): add `stepUrl: z.string().url().optional()` to ExternalPartRef.

2 schema tests (accepts URL, rejects malformed).

Commit: `feat(cad-ir): ExternalPartRef.stepUrl optional field`

### Task 2: compileAssembly emits import_step for external parts with stepUrl

`convex/cad/codegen/compileAssembly.ts` currently skips externals. Update so that externals WITH `stepUrl` get a tiny Python script:

```python
# generated by compileAssembly — external part import
from build123d import *
imported = import_step("/in/external/<vendor>__<partNumber>.step")
# place at origin, rotation
locator = Location((<x>, <y>, <z>), (<rx>, <ry>, <rz>))
positioned = imported.moved(locator)
export_step(positioned, "/out/<id>.step")
```

The result: `compileAssembly(ir): Record<PartId, string>` now produces scripts for both inline parts (build123d construction) and external parts with stepUrl (build123d import + reposition).

Externals WITHOUT stepUrl are still skipped (the assembly references them but no codegen).

3 tests:
- Inline part still produces script (regression)
- External with stepUrl produces import_step script
- External without stepUrl skipped

Commit: `feat(cad-ir): compileAssembly imports STEP files for externals with stepUrl`

### Task 3: Update tools + prompts + README + final sweep

Update `add_part` tool's external variant input_schema with optional `stepUrl: { type: "string", format: "uri" }`. Tools test asserts the new field is accepted.

Prompts: explain when to use stepUrl ("if the vendor publishes STEP, drop the URL here so the assembly compiles with real geometry").

README Phase 18 section.

Final sweep: ~415 tests (411 + 4-5 new), TS ≤ 38.

Commit: `docs(cad-ir): Phase 18 — STEP imports for external parts`

## Out of scope

- **Sandbox-side STEP fetching** — the generated Python references `/in/external/...` paths. Actual fetching/caching needs sandbox infrastructure. Defer.
- **STEP cache invalidation** — assumes URL → file is stable. Real impl needs ETag/hash.
- **Other formats** (IGES, 3MF, OBJ) — STEP-only for v0.
- **Inline STEP data (base64)** — schema accepts URL only.
